# Build And ACL Essentials

This note captures the rules that mattered while fixing `ru.1forma.ru` build failures in `pake-cli`.

## What Broke

Two different problems appeared during the same build pipeline:

1. Tauri build-time ACL validation rejected custom app commands:
   - `allow-list-accounts`
   - `allow-upsert-account`
   - `allow-set-active-account`
2. The generated macOS config pointed at a missing icon:
   - `icons/1forma.icns`

The build failure was not caused by the JS bridge or the Rust `invoke_handler` wiring. The first hard stop was build-time permission resolution.

## Build-Time Rules

### 1. Capability files are not enough by themselves

Keeping permissions only in `src-tauri/capabilities/default.json` is not sufficient if the build-time permission registry does not know about the custom commands.

For this project, the build started succeeding only after adding explicit permission manifests under:

- `src-tauri/permissions/list_accounts.toml`
- `src-tauri/permissions/upsert_account.toml`
- `src-tauri/permissions/set_active_account.toml`

These files must exist as real build inputs, not just as capability references.

### 2. App capabilities and permissions are different layers

- `src-tauri/capabilities/default.json` binds the app capability to the `pake` webview.
- `src-tauri/permissions/*.toml` defines the actual custom command permissions that Tauri’s build script resolves.

If a command is in the capability file but missing from `src-tauri/permissions`, build-time ACL generation can still fail.

### 3. The generated `.pake` config is a build artifact

The file `src-tauri/.pake/tauri.conf.json` is generated by the Pake build pipeline.

It is not safe to assume it always stays in sync with the checked-in platform configs. In this case it still pointed to:

- `icons/1forma.icns`

while the real icon available in the repo was:

- `icons/weekly.icns`

## Critical Paths

The relevant files are:

- `src-tauri/build.rs`
- `src-tauri/capabilities/default.json`
- `src-tauri/permissions/`
- `src-tauri/.pake/tauri.conf.json`
- `src-tauri/tauri.macos.conf.json`
- `projects/ru.1forma.ru/build-new.sh`
- `projects/ru.1forma.ru/scripts/rebuild-local.sh`

## Working Principles

1. Treat build-time ACL as a first-class dependency.
2. Keep capability files and permission manifests synchronized.
3. Never assume `.pake/tauri.conf.json` is safe without inspection.
4. Fix missing build assets in the generated config before blaming Rust or JS.
5. Keep the Rust `invoke_handler` layer and the JS `window.__TAURI__.core.invoke(...)` bridge simple and separate from build-time ACL problems.

## Verification Checklist

Before trusting a build:

- `src-tauri/permissions/*.toml` exists for every custom command
- `src-tauri/capabilities/default.json` references the right webview label
- `src-tauri/.pake/tauri.conf.json` points to real icon assets
- the build command completes without `Permission ... not found`

## Practical Outcome

Once the permission manifests were added and the `.pake` icon path was corrected, the macOS build completed successfully.
